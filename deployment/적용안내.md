# 알림·시간 수정 안내

## 원인

- 첨부 .env에는 검증 알림 설정이 없습니다. 기본값 False이므로 최신 코드도 기존 알림을 보냅니다. UPBIT는 별도 UPBIT_VERIFIED_ALERTS=True도 필요합니다.
- GitHub의 LogMaker.py에 datetime.utcnow().timestamp() 호출이 3곳 남아 있습니다. UTC를 나타내는 naive datetime을 timestamp()가 서버의 로컬 시간으로 해석합니다. Asia/Seoul 서버에서는 9시간 차이가 생깁니다. datetime.now(timezone.utc).timestamp()로 수정했습니다.
- 스크린샷의 TR HL, Exit HL은 청산 이유를 확정할 수 없는 이름입니다. TR이 실제 트레일링 조건이라면 해당 TradingView 알림에 선택 필드 "exit_type":"TRAIL"을 지정하십시오. 일반 전략 종료는 SIGNAL입니다. 이름만으로 수익이나 손실을 확정하지 않습니다.
- 순손익은 기존 보유분의 진입 체결·수수료가 없으면 미확정입니다. VERIFIED_COST_BASIS_COMPLETE=True를 근거 없이 지정하지 마십시오. 기존 메시지 기록은 소급 수정하지 않습니다.

## 기존 PM2 서버: 재설치하지 않고 적용

첨부의 키·비밀번호·Discord URL이 실제 값이라면 거래소/Discord/TradingView에서 교체하십시오. 기존 로그와 cloud-init user-data에도 남았을 수 있습니다. 삭제나 자동 교체는 수행하지 않았습니다.

1. 서버에서 `pm2 describe POA`로 실제 script path, cwd, interpreter를 확인합니다. `/root/POA`가 다르면 아래 경로를 바꿉니다. `git -C /root/POA rev-parse HEAD`와 `timedatectl`을 확인합니다. `pm2 env` 또는 `.env` 전체 내용을 채팅에 보내지 마십시오.
2. TradingView 신규 신호 유입을 중지하고 진행 주문·조회와 미전송 Outbox 상태를 확인합니다. `pm2 stop POA`로 종료한 후 실제 프로세스 종료를 확인합니다. 이 동안 거래 자동화가 멈춥니다. DB를 삭제하거나 과거 DB로 덮어쓰지 않습니다.
3. fix_alerts.py를 서버의 `/root/fix_alerts.py`로 업로드한 뒤 실행합니다.

```bash
python3 /root/fix_alerts.py /root/POA --enable-alerts
chmod 600 /root/POA/.env
```

스크립트는 LogMaker.py와 .env만 수정하고 비공개 백업 폴더를 만듭니다. 기존 API 키·주문 설정·DB 경로는 보존합니다. 설치된 코드에 검증 모듈/설정이 없으면 중단합니다. 이 경우 임의 git pull 대신 검증한 릴리스로 업데이트 계획을 잡아야 합니다.

4. 다음 여섯 플래그가 True인지 확인합니다. 기존 PM2 환경변수에 같은 이름의 False 값이 있으면 .env보다 우선할 수 있으므로 시작 환경도 맞춥니다.

```bash
export VERIFIED_DISCORD_ALERTS=True VERIFIED_FILL_PRICE=True
export DISCORD_OUTBOX_ENABLED=True DISCORD_RETRY_ENABLED=True
export EXIT_REASON_CLASSIFICATION_V2=True UPBIT_VERIFIED_ALERTS=True
pm2 restart POA --update-env
pm2 save
```

기존 PM2 cwd는 바꾸지 마십시오. 상대 경로 notifications.sqlite3의 위치가 달라지면 미전송 이력이 다른 DB에 남습니다. 이것이 불명확하면 재시작 전에 확인해야 합니다. 재시작 자체로 주문을 시험하지 말고, 신호 재개 전 프로세스·설정·작업자 시작 상태를 확인합니다. Discord에는 시작 알림이 발생할 수 있습니다.

기능 롤백: 신규 신호를 중지하고 프로세스·미전송 알림을 확인한 뒤 정지합니다. 스크립트가 출력한 백업의 LogMaker.py와 .env만 복원하고 위 여섯 환경변수도 이전 값으로 복원합니다. DB는 그대로 둡니다. 정상 종료 확인 전 파일을 덮어쓰지 마십시오.

## 새 서버 전용 cloud-config

cloud-config-debian12.yaml은 **Debian 12 amd64** 전용입니다. 기존 Ubuntu 서버에 실행하는 업데이트 스크립트가 아닙니다. JSON은 YAML의 하위 집합이므로 #cloud-config 헤더 아래 JSON 형식으로 작성했습니다.

- Python 3.11 venv, requirements 설치 및 pip check. 기존 버전을 임의 변경하지 않음.
- package_update/package_upgrade 올바른 키, UTC 저장 기준, 단일 NTP 동기화.
- PM2/Node 대신 systemd 하나로 POA 관리. 기존 서버 PM2와 동시에 사용하지 않음.
- 신규 서버에서만 소스 복제·빈 DB 디렉터리 준비. 기존 디렉터리가 있으면 중단. 계정/운영 DB는 배포 ZIP에 포함하지 않습니다.
- PocketBase는 기존 호환 버전 0.16.6을 유지하되 loopback에만 바인딩. 보안 유지보수 상태는 별도 검토 필요.
- Caddy는 배포판 패키지 사용. 템플릿 도메인을 수정하고 검증한 뒤 수동 시작.
- 실제 키를 user-data에 넣지 않음. /root/POA/.env를 서버에서 직접 입력, 권한 0600.
- 설치 커밋은 /root/POA_INSTALLED_COMMIT에 기록. 최신 main 설치이며 검증 릴리스 고정/공급망 무결성 승인은 별도 필요.
- POA·PocketBase는 자동 시작하지 않음. 실제 거래를 허용하는 표식도 만들지 않음.

설치 후 SSH에서 .env에 **새 인증값**과 PocketBase 관리자 정보를 입력합니다. `systemctl start pocketbase`로 빈 DB를 생성하고 SSH 터널로 관리자 화면에 접속해 새 관리자 계정을 만듭니다. DB_ID/DB_PASSWORD를 이 계정과 맞추십시오. 8090 포트를 공개하지 마십시오. 헷지 기능을 사용한다면 기존 kimp 컬렉션 스키마도 별도로 생성/복원해야 합니다. 기존 서버를 새 서버로 이관하는 경우에는 빈 DB 초기화 대신 기존 DB를 안전하게 이관하는 계획이 필요합니다.

Caddy 템플릿 `/root/Caddyfile.poa.template`의 도메인을 고친 뒤 `/etc/caddy/Caddyfile`로 설치하고 `caddy validate --config /etc/caddy/Caddyfile`를 실행합니다. TradingView 송신 IP 목록도 배포 시 확인하십시오. DNS·TLS·방화벽 및 새 키 권한을 확인한 후, 실제 운영 개시를 결정한 경우에만 다음을 실행합니다.

```bash
touch /root/POA/ENABLE_LIVE_SERVICE
systemctl enable --now pocketbase poa caddy
```

설정 후 첫 기동 시 Discord 시작 알림이 발생할 수 있습니다. 이 문서는 서버에 적용되지 않았습니다. Linux 설치, PocketBase 인증, systemd 실제 실행, 512MB 성능 검증은 미완료이며 운영 승인 자료가 아닙니다.
