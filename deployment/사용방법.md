# 앱 전체 ZIP과 설치 코드 v2

사진의 최신 실패는 SOURCE_HASH_MISMATCH입니다. GitHub 커밋 e76269f7에서
배포 해시 43개를 직접 비교했고 `.gitignore` 1개가 불일치했습니다.
앱 실행 파일은 로컬 코드와 일치했습니다.

## GitHub에 먼저 올리기

`POA-app-full-v2.zip`을 PC에서 압축 해제합니다. ZIP 자체가 아니라 **내용물 전체**를
https://github.com/woorin0/POA 의 main 브랜치 루트에 한 번에 업로드하고 커밋합니다.
`main.py`, `exchange/`, `release_manifest_sha256.json`, `.gitattributes`가 저장소 루트에 있어야 합니다.
폴더 하나 아래에 넣거나 옛 해시 목록과 섞지 마세요.
GitHub 업로드 화면에서 숨김 파일도 포함되었는지 확인하세요.
런타임 코드 해시는 LF 기준으로 다시 생성했고 `.gitignore` 등 저장소 메타데이터는
실행 파일 검증에서 제외했습니다. 코드 해시 검증을 끄지는 않았습니다.
설치기에 해시 목록 자체의 SHA-256도 고정되어 있어 반드시 이 ZIP과 이 설치기를 함께 사용해야 합니다.

ZIP에 실제 `.env`, DB, 로그, API 키, Discord 토큰은 포함하지 않았습니다.
기존 GitHub의 `pb_data/`는 ZIP 업로드만으로 삭제되지 않습니다. 공개 저장소의 DB가 실제 계정 데이터를
포함하는지 별도로 점검해야 하며 운영 DB를 삭제하지 마세요.

## 새 서버를 한 번에 설치

Vultr OS는 **Ubuntu 22.04 amd64**를 선택합니다.
`cloud-config-ubuntu2204-v2.yaml` 상단의 JSON에서 다음만 채웁니다.

- `domain`: 서버를 가리키는 실제 도메인
- `PASSWORD`: TradingView 웹훅 JSON의 password와 같은 값
- `DISCORD_WEBHOOK_URL`: 실제 Discord 웹훅 URL
- 사용할 거래소의 KEY / SECRET; OKX·BITGET은 PASSPHRASE도 필요

`release_manifest_sha256`은 수정하지 않습니다. 전체 파일을 Vultr User Data에 넣습니다.
도메인 DNS A 레코드가 서버 IP를 가리켜야 하며 Vultr 방화벽의 80/443을 허용해야 합니다.
필요한 패키지, 독립 Python 환경, PocketBase DB, POA, HTTPS, 재부팅 자동 시작을 설치합니다.
Python은 Ubuntu 22.04 기본 3.10을 사용하며 requirements.txt 버전은 바꾸지 않습니다.
알림 검증 플래그 6개를 켭니다. 확인되지 않은 순손익은 미확정으로 유지합니다.
성공하면 유효한 주문 웹훅을 처리하는 서비스가 자동 시작됩니다.

## 사진의 실패한 서버를 복구

먼저 위 ZIP을 GitHub에 올립니다. `recover-source-v2.py`를 SFTP/WinSCP로
`/root/recover-source-v2.py`에 올린 뒤 서버 콘솔에서 실행합니다.

```bash
sudo python3 /root/recover-source-v2.py
echo "POA_RECOVERY_EXIT_CODE=$?"
```

기존 비공개 입력 파일을 재사용하며 실패한 소스 폴더는 삭제하지 않고
`/root/poa-source-recovery-*`에 보관합니다. `.env`, 가상환경, DB, 운영 중 서비스가
발견되면 안전하게 중단합니다. 이런 중단은 폴더 삭제로 우회하지 마세요.

## 성공 확인

`POA_INSTALL_SUCCESS` 출력과 실제 종료 코드 0을 모두 확인합니다.

```bash
sudo systemctl is-active pocketbase poa caddy
sudo cat /root/POA_INSTALL_RESULT.json
```

서비스 세 개가 active여야 합니다. TradingView Webhook URL은 `https://도메인/order`입니다.
기존 인증 JSON을 사용합니다. UTC 저장 시각은 Discord에서 한국시간으로 표시합니다.
403을 반환하는 루트 GET은 접근 제한 정책이며 주문 테스트가 아닙니다.
복구 뒤에도 이전 cloud-init 실패 기록은 남을 수 있습니다.

실제 Vultr 서버 접근이 없어 Linux 패키지 설치·서비스·TLS·512MB 부하는 미검증입니다.
완료 전에는 설치 성공이나 실거래 배포 승인으로 판단하지 마세요.
